As for the historical dataset [TODO cite historical paper],
we have re-implemented the underlying software and made changes in a number of places,

\subsection{Motivation}
\label{ssec:methods-motivation}

Our method is driven by three key requirements (Sect.~\ref{sec:output-dataset-requirements}).
First, the concentrations should be consistent with the emissions in each scenario [TODO cite Kikstra],
so that the climate outcomes of the ESM simulations can be linked back to the underlying scenarios.
This constraints our available options.
In order to produce GHG concentration forcings for all scenarios on CMIP timelines,
we need a fast running model.
This rules out all full scale ESMs.
Instead we use simple models: a one-box model where it is sufficient
and the simple climate model MAGICC \citep{meinshausen_magicc6-part-1_2011} [TODO cite Meinshausen et al., 2009] otherwise.
MAGICC has demonstrated ability to emulate ESMs [TODO cite RCMIP phase 2, Meinshausen 2011],
was used to produce the CMIP5 and CMIP6 scenario concentrations \citep{meinshausen_ssp-ghgs_2020} [TODO cite Meinshausen et al., 2011 RCP concentrations]
and was used in the IPCC's Sixth Assessment Report (AR6) to provide insights consistent with the AR6 WG1 assessment throughout AR6 \citep{IPCC_AR6-WG1-Ch-7_2021}.
Second, the scenarios must continue smoothly from the historical dataset,
i.e. there should be no spurious jumps at the transition from history to scenario.
This requires us to harmonise the scenarios with the history
to remove any otherwise undesirable artefacts of our modelling approach and the limited time available.
Third, the latitudinal and seasonal structure of the scenario concentrations should be consistent with the historical dataset
and evolve in a way that is informed by history, but which can be driven by quantities that are available in the scenarios all the way out to 2500
(where `available' means either available directly from the emissions scenarios or as output of the simple model runs).
This last requirement is limiting and a key motivator for the relatively simple approach we take
(as in \citealp{meinshausen_ssp-ghgs_2020}).
More complicated approaches may provide improved results,
but generally cannot be applied across the entire timespan from year 1 to year 2500 [TODO see also cite historical paper discussion].

\subsection{General approach}
\label{ssec:methods-general-approach}

As for the historical dataset, our `native resolution'
% TODO-CHECK: {"tag": "native-grid-lat-band-width", "unit": "degree", "lower": 15, "upper": 15}
has monthly temporal resolution and 15\textdegree~latitudinal spatial resolution.
This is the first dataset we generate for all gases.
From the native resolution datasets, we create lower resolution data products
(Sect.~\ref{ssec:methods-derived-grids}).

The scenario datasets are built from the same three components as the historical dataset:
the global-, annual-mean, the seasonality and the latitudinal gradient [TODO cite historical paper].

% TODO move this: belongs with harmonisation
The historical dataset provides the starting point for all three.
We project each component forward in time
from the last year of the historical dataset,
% TODO-CHECK: {"tag": "historical-last-year", "unit": "yr", "lower": 2022, "upper": 2022}
2022,
then combine them as for the historical dataset.

The general approach can be broken down as follows:

\begin{itemize}
    \item {
        \textbf{Step 1: Project the global-, annual-mean}

        We project the global-, annual-mean concentrations using one of three methods.

        \begin{enumerate}
            \item {
                \textbf{Single concentration projection.}
                For the ozone-depleting substances (ODSs) controlled by the Montreal Protocol,
                we use an existing projection from the literature directly
                (\citealp{wmo_ozone-ch7_2022} and, for the HCFCs, \citealp{western_hcfcs_2024}).
                These projections are therefore the same in all scenarios.
                % TODO: check if we need to forward ref the discussion
            }
            \item {
                \textbf{One-box model.}
                For gases with no significant lifetime feedbacks,
                we run a one-box model with the scenario's emissions.
                This allows us to use up-to-date lifetimes \citep[Table A-5,][]{wmo_ozone-ch7_2022}
                in a transparent way
                (without altering the AR6-calibrated configuration of MAGICC [TODO citations]).
            }
            \item {
                \textbf{MAGICC plus harmonisation.}
                % TODO: notes on MAGICCv7.6.0a3, why it's used etc. somewhere
                For all other gases, we run MAGICC v7.6.0a3 with the scenario's emissions,
                take the median of the probabilistic ensemble
                and harmonise this median to the historical dataset.
            }
        \end{enumerate}

        We use the single concentration projection route where such a projection is available,
        the one-box route based on expert judgement about the impact of lifetime feedbacks
        and the impact of updating MAGICC's lifetimes
        [TODO discussion point about this: definitely not ideal, but only affects gases with relatively
        minor radiative forcing so an ok imperfection]
        and MAGICC otherwise.
        % The method used for each gas is listed in Sects.~\ref{ssec:methods-co2}--\ref{ssec:methods-hfc125-like}.
    }

    \item {
        \textbf{Step 2: Project the seasonality and latitudinal gradient}

        For all gases except CO_2,
        the seasonality is projected by multiplying the relative seasonality from the historical dataset
        by the projected global-, annual-mean from Step 1.
        For CO_2, the change in seasonality over time is projected based on MAGICC's net primary productivity (NPP),
        following \citet{meinshausen_ssp-ghgs_2020}.

        For all gases, the latitudinal gradient EOFs come from the historical dataset.
        The first latitudinal gradient PC is projected based on the change in emissions relative to 2022,
        using a linear relationship between the PC and emissions
        (fossil emissions for CO_2 and CH_4, total emissions for all other gases).
        Where a second PC is used (CO_2, CH_4 and N_2O), it is held constant at its 2022 value.
    }

    \item {
        \textbf{Step 3: Prepare the components to be combined}

        As for the historical dataset (and for the same reason),
        the global-, annual-mean and latitudinal gradient PCs are interpolated to monthly timesteps
        using mean-preserving interpolation.
        This interpolation is done such that all scenarios are identical up to the end of 2022
        and agrees with the the historical dataset.
        As for the historical dataset, we adjust the seasonality and latitudinal gradient where needed to avoid negative values.
        % TODO: discussion point on this. Like for the historical,
        % it points to inconsistencies in our methods/input data sources which shouldn't be there,
        % but also only lead to minor corrections in radiative effect terms.
    }

    \item {
        \textbf{Step 4: Generate native resolution}

        As for the historical dataset, we sum the components to give the native resolution dataset [TODO cite historical paper]:

        \begin{equation}
            \label{eq:native-resolution-sum}
            gn(y, m, l) = gm(y, m) + lg(y, m, l) + s(y, m, l)
        \end{equation}
        where $gn$ is the native resolution dataset value,
        $y$ is the year,
        $m$ is the month,
        $l$ is the latitude,
        $gm$ is the global-, annual-mean interpolated to monthly steps,
        $lg$ is the latitudinal gradient
        and $s$ is the seasonality.
        As for the historical dataset, $lg$ has an area-weighted spatial mean of zero
        and $s$ has an annual-mean of zero,
        so the sum does not change the global-, annual-mean.
    }

\end{itemize}

    }
    \item {

        \begin{enumerate}

            }
            \item {
                \textbf{Step 2: Project the seasonality and latitudinal gradient}
                The seasonality is scaled with the global-, annual-mean.
                The first latitudinal gradient PC is projected based on fossil CH_4 emissions.
            }
        \end{enumerate}
    }
    \item {
        N_2O and other gases processed similarly
        % Only put these lists in the sections
        % (HFC-134a, HFC-152a, HFC-23, HFC-245fa, HFC-32 and HFC-365mfc)

        \begin{enumerate}
            \item {
                \textbf{Step 1: Project the global-, annual-mean}
                MAGICC plus harmonisation.
            }
            \item {
                \textbf{Step 2: Project the seasonality and latitudinal gradient}
                The seasonality is scaled with the global-, annual-mean.
                The first latitudinal gradient PC is projected based on total emissions.
            }
        \end{enumerate}
    }
    \item {
        CFC-12 and other gases processed similarly

        \begin{enumerate}
            \item {
                \textbf{Step 1: Project the global-, annual-mean}
                A single concentration projection from the literature, which is the same for all scenarios.
            }
            \item {
                \textbf{Step 2: Project the seasonality and latitudinal gradient}
                The seasonality is scaled with the global-, annual-mean.
                The latitudinal gradient PC is projected based on emissions derived by inverting the single concentration projection.

        \end{enumerate}
    }
    \item {
        HFC-125 and other gases processed similarly

        \begin{enumerate}
            \item {
                \textbf{Step 1: Project the global-, annual-mean}
                One-box model.
            }
            \item {
                \textbf{Step 2: Project the seasonality and latitudinal gradient}
                The seasonality is scaled with the global-, annual-mean.
                The latitudinal gradient PC is projected based on total emissions.
            }
        \end{enumerate}
    }
\end{enumerate}

\subsection{Input emissions scenarios}
\label{ssec:methods-input-emissions}

The input emissions for each scenario come from the CMIP7 ScenarioMIP emissions harmonisation and infilling process
[TODO cite Kikstra et al., Nicholls et al. ScenarioMIP]
and the extensions of these scenarios beyond 2100 to 2500 [TODO cite Sandstad et al.].
We do not describe these here
(for full details, see [TODO cite Kikstra et al., Nicholls et al. ScenarioMIP] and [TODO cite Sandstad et al.]).
The key points for this work are:

\begin{itemize}
    \item {
        % TODO-CHECK: {"tag": "emissions-harmonisation-year", "unit": "yr", "lower": 2023, "upper": 2023}
        the emissions are harmonised to historical emissions estimates in 2023
        (we check this before using them)
        % `notebooks/0020_create-complete-emission-scenario.py`
    }
    \item {
        all species are provided, i.e. the scenarios have already been infilled
        (some minor species are infilled by assuming that they follow the trajectory of another species,
        we re-implemented this infilling as a check that it has been done as we expect)
    }
    \item {
        for the species we project using a single concentration projection (Step 1),
        the emissions up to 2100 are those we infer from the projection (Sect.~\ref{sssec:methods-cfc12-like-project-global-mean}).
        Beyond 2100, the extension process [TODO cite Sandstad et al.] did not use our inferred emissions.
        We run MAGICC with the official emissions, including the official extensions.
        However, the concentrations we provide for these species (based on \citealp{wmo_ozone-ch7_2022} and \citealp{western_hcfcs_2024})
        imply different emissions after 2100 [TODO ref appendix figures].
        % Checked in the 1.1.0 bundle (L): the scenario emissions match our inverse emissions to machine precision up to 2100.
        % After 2100, the official extensions take emissions to (close to) zero,
        % while our concentrations imply emissions which stay roughly constant
        % (e.g. CCl4 in 2300: ~52 kt/yr implied by our concentrations, ~0.06 kt/yr in the official extension).
        This is a mismatch, for these species, between the official extensions and what the official concentrations imply.
        As a result, MAGICC's concentrations of these species are lower than ours after 2100.
        To give a sense of how important this difference is,
        we take, for each species, the maximum (over time) difference in approximate radiative effect
        (concentration difference multiplied by radiative efficiency, \citealp{IPCC_AR6-WG1-Ch-7-SM_2021}, Table 7.SM.7)
        between MAGICC's median and our concentrations, then sum over species.
        % TODO-CHECK: {"tag": "single-projection-magicc-max-erf-difference-sum-l", "unit": "W / m^2", "lower": 0.029, "upper": 0.031}
        In L, this sum is around 0.03~W/m^2
        % TODO-CHECK: {"tag": "single-projection-magicc-max-erf-difference-sum-range", "unit": "W / m^2", "lower": 0.029, "upper": 0.038}
        (0.03--0.04~W/m^2 across the scenarios).
        % Calculated with MAGICC v7.6.0a3 medians vs. `single-concentration-projection_<gas>_annual-mean.feather`, 2022-2500,
        % excluding Halon-1202 (not in our output).
        % Largest contributors in L: CCl4 (0.009), CFC-113 (0.006), CFC-114 (0.005), HCFC-22 (0.003), CFC-12 (0.003).
        % ZNTODO: about 0.009 W/m^2 of the L sum comes from differences before 2100
        % (where the emissions match, so this is MAGICC's lifetimes etc. vs. WMO (2022), not the extensions).
        % Restricting the max to after 2100 gives almost the same sum (0.030 in L), so the headline number is fine,
        % but decide whether to say this.
        % ZNTODO: include this in the discussion (noted there).
        % It's a good illustration of how hard it is to keep all the teams consistent across many decisions.
    }
    \item {
        for CO_2 and CH_4, we also use the emissions split into fossil and biospheric sources
        (this split is used to project the latitudinal gradient, Step 2).
    }
\end{itemize}

We use the emissions as provided, with the emissions in all years (including the historical period) feeding into our projections.
We run MAGICC in emissions-driven mode from 2015 onwards for all gases (Sect.~\ref{sssec:methods-co2-project-global-mean}),
including the gases whose concentrations we take from a single concentration projection or the one-box model.
For many gases, the emissions used to run MAGICC are, up to 2100, those we infer from the projections of
\citet{wmo_ozone-ch7_2022} and \citet{western_hcfcs_2024} [TODO cite Nicholls et al. ScenarioMIP]
(after 2100, they are the official extensions, see above).
This introduces a minor inconsistency between what MAGICC uses to generate its concentration projections
(MAGICC's own, emissions-driven concentrations of every gas)
and what CMIP models will run with (the concentrations we provide).
The inconsistency is minor, particularly given that MAGICC is run emissions-driven for CO_2,
whereas CMIP models will be concentration-driven for CO_2 when they use this dataset.
It does not change the fact that the generated concentrations are sensible boundary conditions for the ESM simulations
(they are not the only sensible answer).

\textbf{Harmonisation.}
The median of the MAGICC ensemble does not exactly match our historical dataset
in the last year of the historical dataset, 2022.
To avoid a jump in concentrations between the historical and scenario datasets,
we harmonise the MAGICC median to the historical global-, annual-mean.
Unlike the harmonisation used in the historical dataset
(which adds a linearly declining offset, see Sect.~[TODO number] of [TODO cite historical paper]),
we use `gradient-aware' harmonisation [TODO cite gradient-aware-harmonisation package].
% `harmonise_splines_add_cubic` from the gradient-aware-harmonisation package,
% used in `notebooks/0031_create-projection-gradient-aware-harmonisation.py`.
% Both timeseries are linearly interpolated between their annual values before harmonising.
In this approach, we add a cubic polynomial to the MAGICC median
such that the result matches both the value and the gradient of the historical global-, annual-mean
in the harmonisation year (2022),
while the cubic and its gradient decline to zero at the `convergence year',
after which the result matches the MAGICC median exactly.
Matching the gradient, as well as the value, avoids a kink in concentrations at the transition from history to scenario,
which would otherwise be visible as a jump in the growth rate.
The convergence year is the harmonisation year plus a gas-specific convergence time.

For CO_2, the convergence time is

chosen to be 15~years as the difference between MAGICC's output and history is small
and we do not want the harmonisation to introduce other artefacts.

\subsubsection{Step 2: Project the seasonality and latitudinal gradient}
\label{sssec:methods-co2-project-seasonality-lat-gradient}

\textbf{Seasonality.}
In the historical dataset, the CO_2 seasonality is the sum of a `base' seasonality
and a seasonality change, which is the product of a seasonality change EOF and PC
(Sect.~[TODO number] of [TODO cite historical paper]).
Historically, the seasonality change PC is driven by a composite of global-mean temperature and CO_2 concentrations.
For the scenarios, following \citet{meinshausen_ssp-ghgs_2020},
we instead project the seasonality change PC based on the global net primary productivity (NPP) from MAGICC.
% `notebooks/1011_scale-seasonality-based-on-magicc-npp.py`
We first derive a linear regression between the historical seasonality change PC and the median NPP from MAGICC
over the historical period
(i.e. the years in which we have both the seasonality change PC from the observation network and MAGICC output,
with MAGICC's historical NPP being the same in all scenarios).
% TODO-CHECK: {"tag": "co2-seasonality-change-npp-regression-years", ...}
We then project the PC with
\begin{equation}
    \label{eq:pc-projection}
    PC(y) = PC(y_h) + \beta \left( x(y) - x(y_h) \right)
\end{equation}
% ZNTODO: move this into a general harmonisation section ?
where $PC$ is the PC being projected,
$y$ is the year,
$y_h$ is the last year of the historical dataset (2022),
$x$ is the quantity which drives the PC (here NPP)
and $\beta$ is the slope of the regression between the PC and $x$.
This form ensures that the PC is continuous at the transition from history to scenario.
As a result, the seasonality change grows (shrinks) as the land biosphere's productivity grows (shrinks)
in each scenario.
As in the historical dataset, the seasonality is then the base seasonality plus the product of the seasonality change EOF
and the projected PC.

\textbf{Latitudinal gradient.}
We use the latitudinal gradient EOFs from the historical dataset,
i.e. we assume that the shape of the latitudinal gradient does not change in the future,
only its magnitude changes (via the PCs).
For CO_2, as in the historical dataset, there are two EOFs.
Following \citet{meinshausen_ssp-ghgs_2020},
the first PC is projected based on the change in fossil CO_2 emissions,
consistent with the historical dataset [TODO cite historical paper].
% `notebooks/1031_scale-latitudinal-gradient-eofs.py`
% The fossil emissions come from the emissions team's fossil/biosphere split file
% (`...harmonised-emissions-fossil-biosphere-aggregation...`, `extract_fossil_biosphere_timeseries`).
To do this, we first derive the relationship between the PC and emissions
with a linear regression between the first PC from the historical dataset
and the historical fossil CO_2 emissions that underpin the scenarios (Sect.~\ref{ssec:methods-input-emissions}).
In the historical dataset, this regression was against emissions from PRIMAP-hist
(Sect.~[TODO number] of [TODO cite historical paper]),
so we re-derive it to be consistent with the emissions in the scenarios.
We use all historical years in which the first PC is not constant
(i.e. the years in which it is derived from observations or emissions, rather than being held constant)
and in which emissions are non-zero.
% TODO-CHECK: {"tag": "co2-lat-gradient-regression-years", ...}
We then project the first PC using Eq.~(\ref{eq:pc-projection}),
with fossil CO_2 emissions as the driver, $x$.
The second PC is held constant at its 2022 value.

\subsubsection{Step 3: Prepare the components to be combined}
\label{sssec:methods-co2-prepare-components}

\textbf{Global-, annual-mean.}
As for the historical dataset, the global-, annual-mean must be interpolated to monthly timesteps using mean-preserving interpolation
(Lai-Kaplan algorithm, \citealp{lai-kaplan_algorithm_2022}, see [TODO cite historical paper].
% `notebooks/1000_interpolate-annual-mean-to-monthly.py`
To ensure that the result joins smoothly onto the historical dataset,
we first join the historical global-, annual-mean (up to 2022) and the projected global-, annual-mean (from 2023)
and then interpolate the joined timeseries.
Mean-preserving interpolation methods, including the Lai-Kaplan algorithm, are not local,
i.e. the monthly values in 2022 depend on the annual-mean values in 2023.
Without further constraints, this would mean that the monthly values in 2022 would differ between scenarios.
We avoid this by setting the value at the boundary between December 2022 and January 2023
(a `wall control point' in the terminology of \citealp{lai-kaplan_algorithm_2022})
to the same value in all scenarios,
specifically the mean of the 2022 and 2023 values across all scenarios.
% TODO-CHECK: {"tag": "scenarios-identical-december-2022", "unit": "dimensionless", "lower": 0, "upper": 1e-4}
% (relative difference between scenarios in December 2022, checked with rtol=1e-4 in the notebook)
As a result, the monthly values are the same in all scenarios up to the end of 2022.
We also constrain the interpolated values to be non-negative.
% ZNTODO: the notebook's check that the monthly values match the historical dataset's monthly values
% (`.isel(time=slice(-6, 0, None))`) selects nothing, so the check never runs.
% The intention was presumably `slice(None, -6)` (i.e. all but the last six months of the overlap).
% Worth fixing and re-checking before we claim agreement with the historical monthly values.
The monthly values in 2022 are not exactly the same as those in the historical dataset,
because the historical dataset's monthly values in 2022 were interpolated using
the 2023 values derived from observations rather than the scenario values.
The differences are negligible [TODO quantify and value check].

\textbf{Seasonality.}
No further processing is required (the seasonality from Step 2 already has a monthly dimension).

\textbf{Latitudinal gradient.}
As for the global-, annual-mean, the PCs are interpolated to monthly timesteps with mean-preserving interpolation,
with the wall control point between December 2022 and January 2023 set to the same value in all scenarios.
% `get_wall_control_points` in `notebooks/1030_*` and `notebooks/1031_*`.
The latitudinal gradient is then the sum over EOFs of the product of each EOF and its monthly-interpolated PC.

% ZNTODO: move this to the first place where it is relevant
\textbf{Avoiding negative values.}
As in the historical dataset, the combination of the components can lead to negative values,
particularly when the global-, annual-mean is small.
For the scenarios, this happens when the concentrations of a gas fall to close to zero
(so it does not affect CO_2, but we describe it here because this step is the same for all gases).
% `notebooks/1100_create-esgf-files.py`
Where the global-, annual-mean is zero, we set the seasonality to zero.
In any year in which the sum of the global-, annual-mean and the latitudinal gradient would be negative,
we scale the latitudinal gradient down by a single factor in that year
so that the minimum value is zero.
For a small number of gases
(HFC-125, HFC-134a, HFC-152a, HFC-245fa, HFC-32, HFC-43-10mee and SO_2F_2),
the sum of all three components can still be negative in some years,
in which case we scale the latitudinal gradient down further in those years.
% ZNTODO: list the gases, scenarios and years in which this happens (value check),
% at the moment the list is just the gases the code allows this for
% (it raises `NotImplementedError` for any other gas).
Because we scale the latitudinal gradient by a single factor in each year,
these adjustments do not change the global-, annual-mean.
This is a crude fix,
and avoiding the need for it is an area for future work (Sect.~\ref{sec:discussion}).

For HCFC-22, HCFC-141b and HCFC-142b, we use the projections from \citet{western_hcfcs_2024}
% Zenodo record 10782689, file `Projections/hcfc_projections_v2.csv`.
rather than \citet{wmo_ozone-ch7_2022}
because they are more recent [ZNTODO: check this is the reason].
The \citet{western_hcfcs_2024} projections end in 2100.
% `notebooks/0001_extend-western-et-al-2024.py`
We extend them to 2500 by assuming that each gas follows a one-box model,
\begin{equation}
    \label{eq:one-box}
    \frac{dC}{dt} = \alpha E - \frac{C}{\tau}
\end{equation}
where $C$ is the global-mean concentration,
$t$ is time,
$E$ is the emissions,
$\tau$ is the gas' atmospheric lifetime
and $\alpha$ converts from emissions (in mass units) to concentrations
(mole fraction in dry air).
% alpha = 1 / (n_atm * 1e-6 / ppm * M_gas), with n_atm = 5.137e18 kg / 28.9 g/mol.
$\alpha$ depends on the molecular mass of the gas
and the number of moles in the atmosphere,
which we calculate from the mass of the atmosphere (5.137 $\times 10^{18}$~kg)
and the molar mass of dry air (28.9~g~mol$^{-1}$) [TODO cite CDIAC conversion table or equivalent].
We use the lifetimes from Table A-5 of \citet{wmo_ozone-ch7_2022}.
% TODO-CHECK: {"tag": "one-box-lifetimes"} (check the lifetimes in the code against WMO 2022 Table A-5)
For the extension, we assume that emissions are constant after 2100,
at the value inferred from the concentration and its rate of change in 2100.
This is a simple and conservative assumption
(it means that concentrations converge towards a steady state rather than declining to zero),
which is acceptable given that the concentrations of these gases are small by 2100.
% ZNTODO: check "small by 2100" with numbers (value check).
The extended projections are then processed as described above for the \citet{wmo_ozone-ch7_2022} projections.

\textbf{Inverse emissions.}
% `notebooks/1020_calculate-inverse-emissions.py`
To run MAGICC (for the other gases, Sect.~\ref{ssec:methods-input-emissions}) and to project the latitudinal gradient (Step 2),
we need emissions which are consistent with the single concentration projection.
We infer these emissions by inverting the one-box model (Eq.~(\ref{eq:one-box})).
We first interpolate the monthly global-mean concentrations (Sect.~\ref{sssec:methods-cfc12-like-prepare-components})
to a resolution of 1/30 of a month using mean-preserving interpolation.
We then calculate the rate of change of concentrations at this resolution
and solve Eq.~(\ref{eq:one-box}) for emissions,
before summing back to annual totals.
We set small negative values (up to 10\% of the maximum emissions in magnitude) to zero.
As a check, running the inverse emissions back through the one-box model reproduces the projected concentrations.

\subsection{Generating concentrations for HFC-125 and similarly processed species}
\label{ssec:methods-hfc125-like}

This difference reflects the fact that, for these gases, there are no significant lifetime feedbacks,
so a one-box model with an up-to-date lifetime is sufficient,
simpler to make consistent with the latest lifetime estimates

\subsection{Preparation for publication on ESGF}
\label{ssec:prep-for-esgf}

As for the historical dataset,
we format the data in a standard way before publishing it.
% TODO-CHECK: {"tag": "n-output-variables", "unit": "dimensionless", "lower": 46, "upper": 46}
We provide the same variable set and five combinations of frequency and grid
as for the historical dataset (Sect.~[TODO number] of [TODO cite historical paper]):

\begin{enumerate}
    % TODO zalue-check: {"tag": "native-grid-lat-band-width", "unit": "degree", "lower": 15, "upper": 15}
    \item mon-gnz: Our native dataset (monthly-means on our native 15\textdegree~latitudinal grid)
    \item mon-gr1z: Monthly-mean hemispheric-means
    \item mon-gm: Monthly-mean global-mean
    \item yr-gr1z: Annual-mean hemispheric-means
    \item yr-gm: Annual-mean global-mean
\end{enumerate}

The key difference from the historical dataset is how the scenario is identified.
The input4MIPs DRS does not have a separate attribute for the scenario.
Instead, the scenario is part of the \texttt{source\_id} attribute,
which also appears in the directory path and filename.
% From `create_source_id` and `create_source_id_extension`
% in `src/cmip7_scenariomip_ghg_generation/input4mips_cvs_helpers.py`.
% TODO-CHECK: {"tag": "source-ids"}
The source IDs are of the form \texttt{CR-[scenario]-[version]},
with the scenario always being written in lowercase
e.g. \texttt{CR-l-1-1-0} for version 1.1.0 of the L scenario.
The data up to the end of 2100 and the data beyond 2100 (the extensions) are published under different source IDs.
The extensions have source IDs of the form \texttt{CR-[scenario]-ext-[version]},
e.g. \texttt{CR-l-ext-1-1-0}.
% TODO-CHECK: {"tag": "output-time-chunks"}
For each scenario, the data from 2022 to 2100 is in a single file per variable, frequency and grid,
while the extensions are split into files covering 100 years each (2101--2200, 2201--2300, 2301--2400 and 2401--2500).
Users therefore have to parse the scenario out of the source ID
in order to identify the files for the scenario they want to run.
We do not go into further detail here.
As for the historical dataset,
the input4MIPs CVs pages \citep{input4mips-cvs_docs_2026},
the user guide [TODO cite scenario user guide]
and the CMIP7 guidance pages
% ZNTODO: repeat link here
(see the introduction)
are the best sources of information on how to find and use these files,
because they can be updated over time.
