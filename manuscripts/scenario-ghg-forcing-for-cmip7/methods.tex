\section{Methods}
\label{sec:methods}

Our methods are based on those in \citet{meinshausen_ssp-ghgs_2020}.
As for the historical dataset [TODO cite historical paper],
we have re-implemented the underlying software and made changes in a number of places,
so we describe the method in full.
Wherever a step is the same as in the historical dataset,
we refer to the historical paper [TODO cite]
for details rather than repeating them.

\subsection{Motivation}
\label{ssec:methods-motivation}

Our method is driven by three key requirements (Sect.~\ref{sec:output-dataset-requirements}).
First, the concentrations should be consistent with the
quantified information used to define the scenarios that underpin each experiment [TODO cite e.g. van Vuuren, Annika's PolMIP stuff],
particularly the emissions in each experiment [TODO cite Kikstra, Annika's PolMIP dataset],
so that the climate outcomes of the ESM simulations can be linked back to the underlying experiment inputs
e.g. socio-economic assumptions and emissions.
This constrains our available options.
In order to produce GHG concentration forcings for all experiments on CMIP timelines from emissions alone,
we need a fast-running, all GHG emissions-driven model.
This rules out all full scale ESMs.
Instead we use simple models: a one-box model where it is sufficient
and the simple climate model MAGICC \citep{meinshausen_magicc6-part-1_2011} [TODO cite Meinshausen et al., 2009] otherwise.
MAGICC has demonstrated ability to emulate ESMs [TODO cite RCMIP phase 2, Meinshausen 2011],
was used to produce the CMIP5 and CMIP6 scenario concentrations \citep{meinshausen_ssp-ghgs_2020} [TODO cite Meinshausen et al., 2011 RCP concentrations]
and was used in the IPCC's Sixth Assessment Report (AR6) to provide insights consistent with the AR6 WG1 assessment throughout AR6 \citep{IPCC_AR6-WG1-Ch-7_2021}.
Second, the projections must continue smoothly from the historical dataset,
i.e. there should be no spurious jumps at the transition from history to projection.
This requires us to harmonise the projections with the history
to remove any otherwise undesirable artefacts of our modelling approach and the limited time available.
Third, the latitudinal and seasonal structure of the projected concentrations should be consistent with the historical dataset
and evolve in a way that is informed by history, but which can be driven by quantities that are available in all experiments all the way out to 2500
(where `available' means either available directly from the emissions or as output of the simple model runs).
This last requirement is limiting and a key motivator for the relatively simple approach we take
(as in \citealp{meinshausen_ssp-ghgs_2020}).
More complicated approaches may provide improved results,
but generally cannot be applied across the entire timespan from year 1 to year 2500 [TODO see also cite historical paper discussion].

\subsection{General approach}
\label{ssec:methods-general-approach}

As for the historical dataset, our `native resolution'
% TODO-CHECK: {"tag": "native-grid-lat-band-width", "unit": "degree", "lower": 15, "upper": 15}
has monthly temporal resolution and 15\textdegree~latitudinal spatial resolution.
This is the first dataset we generate for all gases.
From the native resolution datasets, we create lower resolution data products
(Sect.~\ref{ssec:methods-derived-grids}).

We produce datasets for the ScenarioMIP scenarios [TODO cite]
and for VL-CF, PolMIP's counterfactual to VL [TODO cite] (Sect.~\ref{sec:output-dataset-requirements}),
which we refer to collectively as experiments.
Each experiment follows the historical dataset up to and including
a year which we call its harmonisation year, $y_h$,
and is projected thereafter.
For the ScenarioMIP scenarios, $y_h$ is 2022, the last year of the historical dataset.
VL-CF's emissions diverge from history from 2016 onwards, so, for VL-CF, $y_h$ is 2015.
% From `harmonisation_year = 2015` in the injected parameters of the VL-CF run's notebooks (e.g. `1011`, `1031`),
% vs. the default of 2023 for the markers, which the notebooks cap at the end of the historical dataset (2022).
% The only exception is the gases which we do not model with MAGICC
% (those which use a single concentration projection or the one-box model, see Step 1 below).
% VL-CF's emissions of these gases are the same as VL's,
% so VL-CF's data for these gases is the historical dataset up to 2021 and identical to VL's from 2022 onwards.
% Checked 2026-10-27: official emissions identical for VL and VL-CF (e.g. HFC-125, SF6, CF4, CFC-12, and also CH4 and N2O),
% published VL-CF HFC-125 and CFC-12 global-means equal to history 2016-2021,
% VL-CF native grid equal to VL's 2022-2500 for HFC-125 and SF6.

The datasets are built from the same three components as the historical dataset:
the global-, annual-mean, the seasonality and the latitudinal gradient [TODO cite historical paper].

The general approach can be broken down as follows:

\begin{itemize}
    \item {
        \textbf{Step 1: Project the global-, annual-mean}

        We project the global-, annual-mean concentrations using one of three methods.

        \begin{enumerate}
            \item {
                \textbf{Single concentration projection.}
                For the ozone-depleting substances (ODSs) controlled by the Montreal Protocol,
                we use an existing projection from the literature directly
                (\citealp{wmo_ozone-ch7_2022} and, for the HCFCs, \citealp{western_hcfcs_2024}).
                These projections are therefore the same in all experiments.
                % TODO: check if we need to forward ref the discussion
            }
            \item {
                \textbf{One-box model.}
                For gases with no significant lifetime feedbacks,
                we run a one-box model with each experiment's emissions.
                This allows us to use up-to-date lifetimes \citep[Table A-5,][]{wmo_ozone-ch7_2022}
                in a transparent way
                without altering the AR6-calibrated configuration of MAGICC [TODO citations].
            }
            \item {
                \textbf{MAGICC plus harmonisation.}
                For all other gases, we run MAGICC v7.6.0a3 with each experiment's emissions
                because MAGICC captures key features like climate and concentration feedbacks [TODO cite papers again?].
                From MAGICC's probabilistic output,
                we take the median of the probabilistic ensemble
                and harmonise this median to the historical dataset
                to derive our forcing dataset.
            }
        \end{enumerate}

        We use the single concentration projection route where such a projection is available,
        the one-box route based on expert judgement about the impact of lifetime feedbacks
        and the impact of updating MAGICC's lifetimes
        [TODO discussion point about this: definitely not ideal, but only affects gases with relatively
        minor radiative forcing so an ok imperfection]
        and MAGICC otherwise.
        % The method used for each gas is listed in Sects.~\ref{ssec:methods-co2}--\ref{ssec:methods-hfc125-like}.
    }

    \item {
        \textbf{Step 2: Project the seasonality and latitudinal gradient}

        For all gases except CO_2,
        the seasonality is projected by multiplying the relative seasonality derived in the historical dataset
        by the projected global-, annual-mean from Step 1.
        For CO_2, the change in seasonality over time is projected based on MAGICC's net primary productivity (NPP),
        following \citet{meinshausen_ssp-ghgs_2020}.

        For all gases, the latitudinal gradient EOFs come from the historical dataset.
        The first latitudinal gradient PC is projected based on the change in emissions relative to the harmonisation year,
        using a linear relationship between the PC and emissions
        (fossil emissions for CO_2 and CH_4, total emissions for all other gases).
        % zalue-check: last year holding constant is 2022
        Where a second PC is used (CO_2, CH_4 and N_2O), it is held constant at its value in the harmonisation year.
    }

    \item {
        \textbf{Step 3: Prepare the components to be combined}

        As for the historical dataset (and for the same reason),
        the global-, annual-mean and latitudinal gradient PCs are interpolated to monthly timesteps
        using mean-preserving interpolation.
        This interpolation is done such that the experiments with the same harmonisation year
        are identical up to the end of that year and agree with the historical dataset.
        As for the historical dataset, we adjust the seasonality and latitudinal gradient where needed to avoid negative values.
    }

    \item {
        \textbf{Step 4: Generate native resolution}

        As for the historical dataset, we sum the components to give the native resolution dataset [TODO cite historical paper]:

        \begin{equation}
            \label{eq:native-resolution-sum}
            gn(y, m, l) = gm(y, m) + lg(y, m, l) + s(y, m, l)
        \end{equation}
        where $gn$ is the native resolution dataset value,
        $y$ is the year,
        $m$ is the month,
        $l$ is the latitude,
        $gm$ is the global-, annual-mean interpolated to monthly steps,
        $lg$ is the latitudinal gradient
        and $s$ is the seasonality.
        As for the historical dataset, $lg$ has an area-weighted spatial mean of zero
        and $s$ has an annual-mean of zero,
        so the sum does not change the global-, annual-mean.
    }

\end{itemize}

The high-level summary of which method is used for which gas is provided in the dot points below,
while the specifics for each group of gases are described in the following sections.
Note that Steps 3 (preparing the components) and 4 (generating the native resolution dataset)
are the same for all gases.

\begin{enumerate}
    \item {
        CO_2

        \begin{enumerate}
            \item {
                \textbf{Step 1: Project the global-, annual-mean}
                MAGICC plus harmonisation.
            }
            \item {
                \textbf{Step 2: Project the seasonality and latitudinal gradient}
                The seasonality change PC is projected based on MAGICC's NPP.
                The first latitudinal gradient PC is projected based on fossil CO_2 emissions.
            }
        \end{enumerate}
    }
    \item {
        CH_4

        \begin{enumerate}
            \item {
                \textbf{Step 1: Project the global-, annual-mean}
                MAGICC plus harmonisation.
            }
            \item {
                \textbf{Step 2: Project the seasonality and latitudinal gradient}
                The seasonality is scaled with the global-, annual-mean.
                The first latitudinal gradient PC is projected based on fossil CH_4 emissions.
            }
        \end{enumerate}
    }
    \item {
        N_2O and other gases processed similarly

        \begin{enumerate}
            \item {
                \textbf{Step 1: Project the global-, annual-mean}
                MAGICC plus harmonisation.
            }
            \item {
                \textbf{Step 2: Project the seasonality and latitudinal gradient}
                The seasonality is scaled with the global-, annual-mean.
                The first latitudinal gradient PC is projected based on total emissions.
            }
        \end{enumerate}
    }
    \item {
        CFC-12 and other gases processed similarly

        \begin{enumerate}
            \item {
                \textbf{Step 1: Project the global-, annual-mean}
                A single concentration projection from the literature, which is the same for all experiments.
            }
            \item {
                \textbf{Step 2: Project the seasonality and latitudinal gradient}
                The seasonality is scaled with the global-, annual-mean.
                The latitudinal gradient PC is projected based on emissions derived by inverting the single concentration projection.
            }
        \end{enumerate}
    }
    \item {
        HFC-125 and other gases processed similarly

        \begin{enumerate}
            \item {
                \textbf{Step 1: Project the global-, annual-mean}
                One-box model.
            }
            \item {
                \textbf{Step 2: Project the seasonality and latitudinal gradient}
                The seasonality is scaled with the global-, annual-mean.
                The latitudinal gradient PC is projected based on total emissions.
            }
        \end{enumerate}
    }
\end{enumerate}

\textbf{Best estimate.}

MAGICC's output is probabilistic, spanning the assessed ranges from AR6 over multiple dimensions [TODO citation, I guess AR6 WG1 Ch.7?].
As a result of the requirement to produce a single forcing dataset,
we must reduce this probabilistic output to a single dataset.
We choose to use the median of the probabilistic ensemble as our best estimate
(the probabilistic ensemble's 5--95\% range and chosen median are shown in Fig.~\ref{fig:methods-co2}a,

Other approaches would represent different choices,
e.g. taking a percentile higher than the median would represent a more conservative approach
and picking a specific carbon cycle calibration [as done in][]\citep{meinshausen_ssp-ghgs_2020}
would provide a line of sight to a specific ESM carbon cycle.

\textbf{Harmonisation.}

The historical dataset provides the starting point for all our output datasets.
Our future dataset must diverge from this historical dataset smoothly
to avoid introducing artificial `shocks' or jumps in ESM output based on our forcings.
To avoid such a jump in concentrations between the historical and projected datasets,
we harmonise the MAGICC median to the historical global-, annual-mean (Fig.~\ref{fig:methods-co2}b, c).
% Unlike the harmonisation used in the historical dataset
% (which adds a linearly declining offset, see [TODO cite historical paper]),
To ensure that both the absolute value and the gradient are continuous,
we use `gradient-aware' harmonisation [TODO cite gradient-aware-harmonisation package].
% `harmonise_splines_add_cubic` from the gradient-aware-harmonisation package,
% used in `notebooks/0031_create-projection-gradient-aware-harmonisation.py`.
% Both timeseries are linearly interpolated between their annual values before harmonising.
In this approach, we add a cubic polynomial to the MAGICC median
such that the output dataset matches both the absolute value and the gradient of the historical global-, annual-mean
in the harmonisation year.
The additional cubic and its gradient decline to zero in a specified `convergence year',
after which the result follows the output MAGICC median.
Matching the gradient, as well as the value, avoids a kink in concentrations at the transition from history to projection,
which would otherwise be visible as a jump in the growth rate (Fig.~\ref{fig:methods-co2}b).
% From `convergence_time_delta` in `notebooks/0031_create-projection-gradient-aware-harmonisation.py`.
For CO_2, the convergence time is
% TODO-CHECK: {"tag": "co2-harmonisation-convergence-time", "unit": "yr", "lower": 15, "upper": 15}
chosen to be 15~years as the difference between MAGICC's output and history is small
and we do not want the harmonisation to introduce other artefacts.
This harmonisation approach is a `band-aid' approach to work around inconsistencies between the historical dataset and our methods
that introduces other artefacts, for example the fact that the harmonisation effect differs across experiments.
Future work should consider more robust approaches that do not require such workarounds (Sect.~\ref{sec:discussion}).

\subsubsection{Step 2: Project the seasonality and latitudinal gradient}
\label{sssec:methods-co2-project-seasonality-lat-gradient}

\textbf{Seasonality.}
In the historical dataset, the CO_2 seasonality is the sum of a `base' seasonality and a seasonality change [TODO cite historical paper].
The seasonality change is then the product of a seasonality change EOF and PC.
Historically, the seasonality change PC is driven by a composite of global-mean temperature and CO_2 concentrations.
For the projections, following \citet{meinshausen_ssp-ghgs_2020},
we instead project the seasonality change PC based on the global net primary productivity (NPP) from MAGICC
(Fig.~\ref{fig:methods-co2}d, see Sect.~\ref{sec:discussion} for a discussion of this inconsistency between the historical and projection methods).

% `notebooks/1011_scale-seasonality-based-on-magicc-npp.py`
We first perform a linear regression between the historical seasonality change PC and the median NPP from MAGICC
over the historical period
(i.e. the years in which we have both the seasonality change PC from the observation network and MAGICC output,
Fig.~\ref{fig:methods-regressions-co2}a).
% TODO-CHECK: {"tag": "co2-seasonality-change-npp-regression-years", ...}
% ZNTODO: note in the text (and return to in the discussion, Sect. \ref{sec:discussion})
% that the seasonality change PC vs. NPP regression was re-calculated for VL-CF, and differs from the markers' one.
% Notebook `1011` regresses over the years up to the harmonisation year,
% which is 2015 for VL-CF rather than 2023 for the markers:
% the markers use 1981-2023 (slope 1.28 yr / GtC), VL-CF uses 1981-2015 (slope 1.78 yr / GtC).
% So the same NPP change gives VL-CF's seasonality change PC roughly 40% more change than the markers'.
% (From our re-run of the VL-CF notebook, `manuscript-outputs/rerun-markers/regressions/co2-seasonality-change-vl-cf_regression.json`.)
% Related: the seasonality change PC projection is anchored in 2023, not 2022
% (the historical seasonality change PC runs to 2023 because the observations do),
% so $y_h$ below is 2023 for the seasonality and every experiment, including VL-CF,
% uses the historical seasonality change PC up to and including 2023.
We then project the PC with
\begin{equation}
    \label{eq:pc-projection}
    PC(y) = PC(y_h) + \beta \left( x(y) - x(y_h) \right)
\end{equation}
where $PC$ is the PC being projected,
$y$ is the year,
$y_h$ is the harmonisation year (Sect.~\ref{ssec:methods-general-approach})
% This shouldn't have been the same for all experiments, that's a bug.
% We might release a corrected dataset in case anyone wants
% to explore the impact of the difference
% but that is expected to be small based on Meinshausen 2020.
% ;
% for the seasonality change PC, $y_h$ is 2023 in all experiments,
% because the historical seasonality change PC extends to 2023),
$x$ is the quantity which drives the PC (here NPP)
and $\beta$ is the slope of the regression between the PC and $x$.
This form ensures that the PC is continuous (i.e. harmonised) at the transition from history to projection.

\textbf{Latitudinal gradient.}
We use the latitudinal gradient EOFs from the historical dataset.
Consistent with the historical dataset,
we assume that the shape of the latitudinal gradient does not change,
only its magnitude (via the PCs).
For CO_2, as in the historical dataset, there are two EOFs.
Following \citet{meinshausen_ssp-ghgs_2020},
the first PC is projected based on the change in fossil CO_2 emissions,
i.e. all emissions which originate from fossil reservoirs (as opposed to originating from the biosphere),
consistent with the historical dataset [TODO cite historical paper].
% `notebooks/1031_scale-latitudinal-gradient-eofs.py`
% The fossil emissions come from the emissions team's fossil/biosphere split file
% (`...harmonised-emissions-fossil-biosphere-aggregation...`, `extract_fossil_biosphere_timeseries`).
To do this, we first derive the relationship between the PC and emissions
with a linear regression between the first PC from the historical dataset
and the historical fossil CO_2 emissions that underpin the scenarios
(Sect.~\ref{sssec:methods-co2-project-global-mean}, Fig.~\ref{fig:methods-regressions-co2}b).
In the historical dataset, this regression was against emissions from PRIMAP-hist
[TODO cite historical paper],
so we re-derive it to be consistent with the historical emissions that underpin the CMIP7 scenarios [TODO cite Kikstra and underlying datasets].
We use all years in which the first PC is not constant
(i.e. the years in which it is derived from observations or emissions)
and in which emissions are non-zero.
% TODO-CHECK: {"tag": "co2-lat-gradient-regression-years", ...}
We then project the first PC using Eq.~(\ref{eq:pc-projection}),
with fossil CO_2 emissions as the driver, $x$ (Fig.~\ref{fig:methods-co2}e).
The second PC is held constant at its value in the harmonisation year (Fig.~\ref{fig:methods-co2}e).

\subsubsection{Step 3: Prepare the components to be combined}
\label{sssec:methods-co2-prepare-components}

\textbf{Global-, annual-mean.}
As for the historical dataset, the global-, annual-mean must be interpolated to monthly timesteps using mean-preserving interpolation
(where we use the Lai-Kaplan \citealp{lai-kaplan_algorithm_2022} and Rymes-Myers algorithms \citealp{rymes-myers_algorithm_2001},
see [TODO cite historical paper]).
% `notebooks/1000_interpolate-annual-mean-to-monthly.py`
To ensure that the result joins smoothly onto the historical dataset,
we first join the historical global-, annual-mean (up to the harmonisation year) and the harmonised, projected global-, annual-mean (thereafter)
and then interpolate the joined timeseries.
The reason for this is that mean-preserving interpolation methods like the one we use are not local,
e.g. for the ScenarioMIP scenarios, the monthly values in 2022 depend on the annual-mean values in 2023.
Without further constraints, this would mean that the monthly values in the harmonisation year would differ between experiments.
We avoid this by setting the value at the boundary between December of the harmonisation year and January of the following year
(a `wall control point' in the terminology of \citealp{lai-kaplan_algorithm_2022})
to the same value in all experiments with the same harmonisation year,
specifically the mean of the values in the harmonisation year and the following year across these experiments.
% TODO-CHECK: {"tag": "scenarios-identical-december-2022", "unit": "dimensionless", "lower": 0, "upper": 1e-4}
% (relative difference between scenarios in December 2022, checked with rtol=1e-4 in the notebook)
As a result, the monthly values are the same in all experiments with the same harmonisation year up to the end of that year.
We also constrain the interpolated values to be non-negative.
% ZNTODO value check here: the notebook's check that the monthly values match the historical dataset's monthly values
% (`.isel(time=slice(-6, 0, None))`) selects nothing, so the check never runs.
% The intention was presumably `slice(None, -6)` (i.e. all but the last six months of the overlap).
% Worth fixing and re-checking before we claim agreement with the historical monthly values.
For the ScenarioMIP scenarios, the monthly values in 2022 (which are part of our output) are not exactly the same as those in the historical dataset,
because the historical dataset's monthly values in 2022 were interpolated using
2023 values derived from observations rather than the values derived by our method.
The differences are negligible [TODO quantify and value check].

\textbf{Seasonality.}
No further processing is required (the seasonality from Step 2 already has a monthly dimension).

\textbf{Latitudinal gradient.}
As for the global-, annual-mean, the PCs are interpolated to monthly timesteps with mean-preserving interpolation,
with the wall control point between December of the harmonisation year and January of the following year
set to the same value in all experiments with the same harmonisation year.
% `get_wall_control_points` in `notebooks/1030_*` and `notebooks/1031_*`.
The latitudinal gradient is then the sum over EOFs of the product of each EOF and its monthly-interpolated PC.

% `notebooks/0001_extend-western-et-al-2024.py`
We extend them to 2500 (Fig.~\ref{fig:methods-western-et-al-2024})
by assuming that each gas follows a one-box model,
\begin{equation}
    \label{eq:one-box}
    \frac{dC}{dt} = \alpha E - \frac{C}{\tau}
\end{equation}
where $C$ is the global-mean concentration,
$t$ is time,
$E$ is emissions,
$\tau$ is the gas' atmospheric lifetime
and $\alpha$ converts from emissions (in mass units) to concentrations
(mole fraction units).
% alpha = 1 / (n_atm * 1e-6 / ppm * M_gas), with n_atm = 5.137e18 kg / 28.9 g/mol.
$\alpha$ depends on the molecular mass of the gas
and the number of moles in the atmosphere,
which we calculate from the mass of the atmosphere (5.137 $\times 10^{18}$~kg)
and the molar mass of dry air (28.9~g~mol$^{-1}$) [TODO cite CDIAC conversion table or equivalent].
We use the lifetimes from Table A-5 of \citet{wmo_ozone-ch7_2022}.
% TODO-CHECK: {"tag": "one-box-lifetimes"} (check the lifetimes in the code against WMO 2022 Table A-5)

at the value inferred from the concentration and its rate of change in 2100.
This is a simple and conservative assumption
that means that concentrations converge towards a steady state rather than declining to zero.

\subsubsection{Step 1: Project the global-, annual-mean}
\label{sssec:methods-hfc125-like-project-global-mean}

% `notebooks/0030_create-projection-one-box-model.py`
We project the global-, annual-mean concentrations with the one-box model
described in Sect.~\ref{sssec:methods-cfc12-like-project-global-mean} (Eq.~(\ref{eq:one-box})),
again using the lifetimes from Table A-5 of \citet{wmo_ozone-ch7_2022}
(for SF_6, we use the mean of the two lifetimes given, 850 and 1280~years).
We start the one-box model from the historical dataset's global-, annual-mean in 2022
and run it forward with the emissions in each experiment (Sect.~\ref{sssec:methods-co2-project-global-mean}),
using a forward Euler scheme with monthly timesteps
(the emissions in year $y$ drive the change in concentrations from year $y$ to year $y+1$
% ZNTODO: check constancy assumption
and are assumed to be constant over the year).
Because the one-box model starts from the historical dataset's value, no harmonisation is required
(Fig.~\ref{fig:methods-hfc125}a).
% ZNTODO: unlike the gradient-aware harmonisation, this doesn't guarantee that the growth rate is continuous at 2022
% (the growth rate in 2023 is set by the scenario emissions and the lifetime, not the historical growth rate).
% Check how big the kinks are (appendix figure of the join, see the figure plan at the top).
For these gases, MAGICC is also run (as it is for all gases, Sect.~\ref{sssec:methods-co2-project-global-mean}),
but its concentrations for these gases are only used to compare with the one-box model, not in our output
(Fig.~\ref{fig:methods-hfc125}a and Appendix~\ref{app:methods-figures-hfc125-like}).

\begin{enumerate}

\subsection{Preparation for publication on ESGF}
\label{ssec:prep-for-esgf}

As for the historical dataset,
we format the data in a standard way before publishing it.
% TODO-CHECK: {"tag": "n-output-variables", "unit": "dimensionless", "lower": 46, "upper": 46}
We provide the same variable set and five combinations of frequency and grid
as for the historical dataset [TODO cite historical paper]:

\begin{enumerate}
    % TODO zalue-check: {"tag": "native-grid-lat-band-width", "unit": "degree", "lower": 15, "upper": 15}
    \item mon-gnz: Our native dataset (monthly-means on our native 15\textdegree~latitudinal grid)
    \item mon-gr1z: Monthly-mean hemispheric-means
    \item mon-gm: Monthly-mean global-mean
    \item yr-gr1z: Annual-mean hemispheric-means
    \item yr-gm: Annual-mean global-mean
\end{enumerate}

The key difference from the historical dataset is how the experiment is identified.
The input4MIPs DRS does not have a separate attribute for the experiment.
Instead, the experiment is part of the \texttt{source\_id} attribute,
which also appears in the directory path and filename.
% From `create_source_id` and `create_source_id_extension`
% in `src/cmip7_scenariomip_ghg_generation/input4mips_cvs_helpers.py`.
% TODO-CHECK: {"tag": "source-ids"}
The source IDs are of the form \texttt{CR-[experiment]-[version]},
with the experiment always being written in lowercase
e.g. \texttt{CR-l-1-1-0} for version 1.1.0 of the L scenario.
This requires care to parse when there is a hyphen in the scenarion name,
e.g. for VL-CF we have \texttt{CR-vl-cf-1-1-0} for version 1.1.0 of VL-CF.
% From the published file names in the 1.1.0 bundle.
% The ScenarioMIP scenarios are published under the ScenarioMIP activity and VL-CF under the PolMIP activity.
The data up to the end of 2100 and the data beyond 2100 (the extensions) are published under different source IDs.
The extensions have source IDs of the form \texttt{CR-[experiment]-ext-[version]},
e.g. \texttt{CR-l-ext-1-1-0}.
% TODO-CHECK: {"tag": "output-time-chunks"}
% For each scenario, the data from 2022 to 2100 is in a single file per variable, frequency and grid,
% while the extensions are split into files covering 100 years each (2101--2200, 2201--2300, 2301--2400 and 2401--2500).
Users therefore have to parse the experiment out of the source ID
in order to identify the files for the experiment they want to run.
We do not go into further detail here.
